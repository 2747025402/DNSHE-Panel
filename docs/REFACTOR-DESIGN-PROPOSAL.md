# DNSHE 全站重构设计方案

日期：2026-10-17。状态：**已进入实施；本稿是需求与验收基线，不是完成或部署记录。**

本稿结合逐页反馈、独立设计／实用性评审及当前代码检查。它记录过一次隔离候选验证；具体部署地址、账号数据和内部证据不属于公开交付内容。各项当前进度与限制统一见 `DELIVERY.md`，旧审查事实保留其历史时点。

## 1. 判断与范围

当前失败不是“不够花”，而是把设计感误写成了英文眉题、大口号、无名节点和长轨道。数据风中已经成熟的卡片、表格、绑定控件不能被推倒；设计风也不能以隐藏名称、减少操作、增加说明为代价。

新方向：**数据风是完整管理工作台；设计风是同一业务的资产编排与证据阅读。** 两者均须完成相同主动作，不将设计风降格成只看不能用的概念稿。

| 保留 | 重做 | 删除 |
| --- | --- | --- |
| 用户认可的域名资产、账号与助力、账户配额基本信息 | 设计风的信息顺序、主辅关系、对象与详情关系 | “域名不需要一墙卡片”等设计师自述 |
| 数据风的卡片／表格、顶部双绑定控件 | 最近注册、CF 摘要、助力与账号的规模化布局 | 重复标题、无意义英文眉题、巨大零值统计 |
| 域名基线、域名状态梯条的图形语言 | 点阵的用途：只作摘要，不作唯一查找入口 | 页内第二套画风开关、与正文无关的列数控件 |
| 既有 DNS、委派、续期、复制、Secret 控件 | 权限诊断、日志刷新、简单批量查重 | 永久空检查器、虚构趋势和无尺度短线 |

## 2. 两种画风的明确职责

| 维度 | 设计风 | 数据面板风 |
| --- | --- | --- |
| 第一眼 | 当前资产结构、重点对象、变化和下一步 | 数量、异常、搜索、比较和批量操作 |
| 页面骨架 | 主图形／主对象清单＋辅助上下文；选择后才出现详情 | 工具带＋同列线列表／表格；详情紧跟对应行 |
| 图表 | 数据有意义时使用容量尺、状态基线、事件时间线 | 紧凑状态轨、比较条、按需趋势 |
| 对象名称 | 必须直读，不靠逐点 hover 猜身份 | 固定身份列，长名称有完整查看路径 |
| 操作 | 主动作邻近对象，低频操作进检查器 | 高频行内、批量共带、低频更多菜单 |
| 数量增长 | 分组目录、渐进展开、按需详情 | 搜索／筛选／排序／分页 |
| 业务能力 | 与数据风一致，不隐藏 Key、Secret 或 DNS 入口 | 不因密度高而丢字段或失败原因 |

全局只保留“设计／数据”一处状态来源；明暗主题独立。数据风内的“卡片／表格”是局部视图，不再被叫成另一种画风。已有视图、列数、筛选、折叠和草稿不被静默迁移或重置。

设计风不强迫每页都画图：表单、密钥、设置可以通过排印、共同锚线和细节层次形成设计；没有真实数据关系就不画关系网。

## 3. 统一视觉与组件语言

- **网格**：沿用项目间距令牌；主区用明确 3:2、2:1 或通栏关系，不是任意大小的卡片拼贴。同排共享上下沿；不靠拉高空卡制造等高。
- **排印**：系统无衬线、数字等宽。页标题稳定，删除第二个口号标题；大数字只强调关键事实，不把每模块都做 Hero。
- **分隔**：统计带内部发丝线，工作模块间使用统一间距；线不贴输入、按钮、文字。工具带分隔线上下保留约 12–16px 空间，不单纯删掉所有边线。
- **配色**：黑白灰为结构，中性灰黑夜间；状态色仅表达真实成功／告警／失败，不用蓝紫粉、辉光、渐变填设计空白。
- **控件**：沿用项目 40px 工具带规格，同排等高；手机命中按 44px 预算。短文案不折行，长业务内容不裁掉唯一身份。展开用“展开／收起”等语义，避免装饰箭头。
- **检查器**：未选中时不常驻空栏；选中才出现。宽屏相邻，窄屏覆盖；可关闭、Esc、归焦，内部按钮不误触行选择。
- **动效**：只表达选中、展开和范围变化；短、可中断、支持减少动效，不逐卡漂浮入场。
- **空态**：一个事实＋一个下一步；不同时渲染四个零值统计、空队列、空清单和空历史。

## 4. 逐页重构

### 4.1 概览

**保留**：用户满意的域名资产、账号与助力；账户配额基本关系；数据风的状态轨道。

**数据风：合并现有好模块，作为完整管理基线。**

1. 顶部一行：域名总量、即将到期、读取异常、更新时间；健康时不堆多张恒为零的诊断卡。
2. 域名状态：明确总量 `N`；“已委派／未委派”与“活跃／过期”分成两个独立维度，各自标分母，不将重叠状态加在一起。
3. 中部：账户配额比较＋CF 实际用量摘要。CF 显示今日已读用量、每账号额度、最高单账号使用率、覆盖数与缓存标记。
4. 最近注册降为紧凑事件列表，域名、归属、完整日期直读；点击定位对象。少数据不强制与长配额表等高。

**设计风：资产版面，而非再摆一组普通卡。**

```text
域名总量      委派结构（独立分母）      生命周期（独立分母）
──────────────────────────────────────────────────────
账户容量尺／重点账号（主区）       CF 用量与最高压力（辅区）
──────────────────────────────────────────────────────
最近注册时间基线                  账号与助力短摘要／动作
```

近期注册采用日期分组、域名身份和变化顺序，不用一条没有真实时间意义的折线。CF 图形强调最高单账号压力，详细趋势留在额度页；首屏不是七天图表展览。

**必修数据问题**：当前 `buildOverviewCfUsage` 在全覆盖时会将账号额度相加后算百分比。A 用 110%、B 用 0%，不能显示 55% 并暗示安全。总用量可合计；风险显示“已读账号中最高使用率＋账号名”，缺覆盖时明确局部，不声称全局最大值。

### 4.2 域名列表

**数据风保留**：卡片／表格、完整名字、账号分组、DNS／委派／续期及导出。修工具带贴线：筛选层、统计与动作层有清楚间距，不再多堆一排卡。

**设计风重做为有名字的资产目录**：

- 顶部基线表示账号资产分布、状态与数量，保留用户喜欢的点阵／基线气质。
- 正文始终显示域名名称，不能因为“只有 10 个对象”就退回无名圆点。
- 主体采用“账号目录＋域名清单”；选择后在邻近检查器展示日期、DNS 来源和操作。窄屏不同时挤三栏。
- 点阵只做汇总或筛选入口，不作为每个域名的唯一命中点。数量很大时聚合并显示精确数，不画 500 个难点的节点。
- 同一账号折叠状态由共享状态控制；“收起全部”必须真的作用于当前视图。只有卡片正文才显示列数设置。

可比较的模块稿：A 为“基线摘要＋名称清单”，B 为“到期时间尺＋名称清单”；B 仅展示真实到期日期，永久／未知放独立区域，不强塞时间轴。两案复用同一数据和动作，不各造整站。

### 4.3 Cloudflare 资产

数据风保留用户认可的 Zone 卡片／表格。设计风借域名页的共同锚线，不复制无名星座图：

- 账号覆盖／激活分布为摘要，Zone 名称为正文主入口。
- 当前 Zone 的名称服务器、激活状态、DNS／传播检查在检查器；不把 NS 状态、API 可读性混成一种“正常”。
- 失败账号仍保留并说明原因，不能消失或变成“0 Zone”。
- 收起、排序、搜索作用于真实正文；切换视图不沿用过期选择对象。

### 4.4 域名助力

主动作分成两条清楚路径：“给好友助力”和“获取自己的助力码”，不要混成一整墙卡片。

**设计风**：好友助力输入／消耗预览为主；可参与账号队列为辅；自己的域名按账号折叠，选中后才展示明细；历史在下方紧凑时间线。

**数据风**：保留额度比较表与移动摘要卡；账号额度模块可整体收起，域名清单按账号收起；页内切换“域名／记录”，避免两套长列表同时展开。

两种风格都提供账号搜索、只看可参与、明确排除原因。20 个账号各 25 个域名时，不能默认展开 500 个对象。未知助力次数显示“未读取”，不由 `?? 0` 变为“已用完”。最终确认列明参与账号和消耗；取消零写入。

### 4.5 账号管理

**必须保留用户认可的顶部双绑定控件**，两种风格都保留其位置、等宽关系和真实动作。

数据风继续分提供商的紧凑目录。设计风采用“连接目录”：提供商分区、账号身份、真实验证状态、已有资源摘要，选择后打开凭据／权限检查器。没有实际关联字段，不画虚假的账号连线网。

“已绑定”“凭据验证通过”“资源可读”是三种事实，不因数据库有记录就写“已连接正常”。资源数量仅在已有数据时显示，不为美观临时发几十条请求。

高数量提供商分组可收起；搜索结果直接定位，不需要先展开全部账号。编辑／解绑保留；解绑仍确认，不新增一键批量解绑。

### 4.6 API 密钥

页名固定为“API 密钥”。删除“轨道上的凭据”等无效备注、巨大 `0/0` 和无尺度装饰短线。

**设计风**：按账号组织凭据账本，名称、状态、累计请求、最后使用共线；整行选中后才显示二级检查器。未选择时列表用全宽，不永久预留空白。

**数据风**：保留完整管理表与紧凑操作，所有同类能力仍可达。

检查器必须提供完整 API Key、复制；Secret 的显示／隐藏／复制、现有重新生成流程。没有保存的 Secret 明确说明“本地未保存，无法取回”，不谎称凭据不存在。缺失最后使用时间标“未返回”，只有上游明确表示从未使用才写“从未使用”。

累计请求无逐日数据时不画七天趋势；如保留请求比较条，同一批次统一线性尺度，数字和单位可见，否则删除。

### 4.7 注册／查重

页内工作面收敛为“单个／批量／历史”。批量默认简单表单，复杂规则进入高级选项。

- 快捷任务：“两位数字”“三位数字”“两位字母数字”等名称必须与真实字符集一致。
- 明确范围：“数字 00–99 × 选中后缀”，启动前显示实际候选数；单后缀两位数字就是 100 个，不把字母数字两位 1296 个冒充两位数字。
- “全部”必须有限定：全部后缀／全部当前候选，不使用含义无限的“全部查重”。大范围需要确认和可暂停，不自动全量扫远端。
- 扫描时保留进度、已确认结果、错误／限流及暂停／继续／停止；全局并发与每账号限频有界，不随 100 个账号变为 100 路并发。
- 历史保存完整配置：模式、字符集、位数、起点、排除、后缀与账号范围、完成／暂停状态。恢复只回填，不自动开始，不丢顺序生成模式。
- 数据风为运行操作台；设计风将任务入口、结果和历史分主辅，不把实时结果藏到巨大步骤卡后。

### 4.8 账户配额

数据风与可用管理能力保留，不推倒“暂时还可以”的部分。设计风重做容量尺和按需分解，删除双标题与无动作的“打开详情”口号。

- 默认比较使用压力：每账号一条 0–100% 共尺度，旁边明确 `已用／总额`、可用量；超过 100% 数字不截成 100%，溢出有明确状态。
- 如比较实际容量，则另用统一数量尺度，已用与总量都映射到该尺度；不混用“总量缩放轨道＋全宽百分比黑段”。
- 点击账号展开已有基础额度、奖励、当前域名数和错误；没有真实字段不加空模块。
- 账号多时支持搜索、高压力优先和分组收起；读取失败不能排成最低压力。

### 4.9 动态 DNS

先给明确标注的模拟预览，不替用户创建绑定或更新 DNS。

- 设计风展示绑定对象、最近 IP／更新时间及真实可得的执行事件；数据风用任务状态列表。**真实绑定也用这两套结构**，不能只在空态模拟区有区别。
- 合成场景覆盖正常、IP 未变化、超时、重试、从未更新；使用保留示例域名／IP，不含真人令牌。
- 模拟开关可关，真实运行与模拟数据不混排。无真实事件历史时只显示最近结果，不补造时间线。
- 设备脚本、复制、编辑、删除等复用既有动作；“立即更新”属于真实写操作，不在设计评审中执行。

### 4.10 CF 免费额度

只服从顶栏全局画风，不保留页内第二套“设计／数据”切换。

**数据风**：范围／刷新 → 一行状态 → 账号比较表。整行点击展开，详情紧跟所点账号，排序后仍跟稳定 ID；内部链接、复制等不冒泡触发展开。Enter／Space、Esc 和归焦可用。

**设计风**：用量结论＋资源容量尺 → 一张适度大小的范围趋势＋必要峰值信息 → 可选账号明细。不为每账号常驻一张大七天图。趋势每一天都能 hover、聚焦、点按固定，零值和缺失同样可命中。

只在有可靠日历史的指标提供日期维度；快照资源不能冒充逐日曲线。多账号上限不是可共享资金池，展示最高单账号压力；缓存和覆盖不可隐藏。

**文案减法**：把多段解释压成“Pages 权限待核对”“R2 未启用”“保留缓存 · 时间”等事实；完整接口、错误码、范围和原始错误放可展开诊断。不删除真实错误，只删除重复解释。

**权限修复必须形成可复查链路**：

1. 盘点本页实际调用的每个 REST／GraphQL 数据集及资源范围。
2. 建立接口 → 权限 → Token 模板 key/type → 目标账号／Zone 的对应表，模板与手动清单同源。
3. 核对生成链接到 Cloudflare 表单后实际出现的权限，不能只测试 URL 含字符串。
4. 对当前账号各资源只读检查，区分认证无效、权限缺失、账号范围不符、服务未启用、超时／限流、成功空集、历史窗口不足。
5. 模板修正不使已签发 Token 自动升级；需要时提供明确的重新申请／替换路径，不私自轮换凭据。

已核实官方 Pages 列举接口存在，接受 Pages Read 或 Pages Write；本地模板已有 `page:edit`。因此当前 `Authentication error` 的根因仍待凭据与账号范围实测，不能笼统说“Pages 本身不能获取”，也不能保证再加权限必定修复。[Pages 接口](https://developers.cloudflare.com/api/resources/pages/subresources/projects/methods/list/)

模板 URL 只负责预填，不完成创建；官方格式是编码的 `key/type` 数组。已有 Token 不会因本地常量变化而改变。[Cloudflare 模板文档](https://developers.cloudflare.com/fundamentals/api/how-to/account-owned-token-template/)

### 4.11 运行日志

本地已有刷新、防重复点击、成功读取时间与失败保旧数据，但仍需候选验收。

- 刷新实际产生新请求，新增日志可见；失败不更新“最近成功时间”，不先清空旧列表。
- 用户停留在较早位置时提示“有 N 条新日志”，不强行跳走；已在顶部才直接更新最新内容。
- 设计风为日期／事件阅读，数据风为时间、级别、模块、对象、消息列。长详情按行展开，不横向撑破页面。
- 刷新、筛选共带，“清空”是次级危险动作。当前最近 100 条的限制需明示；若要全历史，必须服务端游标／时间范围，不能只做假分页。
- 不默认给全站加轮询。需要实时模式再提供明确开关，后台页暂停，避免资源与上游消耗。

用户本条末尾“而且我希望很多页面”未完整说明；本稿只纳入已有真实来源页的统一刷新规范，不推断成全站自动刷新需求。

### 4.12 设置及全局框架

设置不为画风强画图：设计风按任务编排、状态与编辑分层；数据风紧凑分组表单。两者保留相同设置、搜索、保存与失败保稿。

全局切换保持路由、主题、搜索、账号范围、排序、选中、折叠和草稿。切换不额外发送相同接口，不以重新挂载整页触发动画。移动导航沿用已确认的顶部抽屉，不新增侧栏层级。

## 5. 规模与数据语义合同

| 测试规模 | 设计与交互要求 |
| --- | --- |
| 1 账号／10 对象 | 名称直读，不显示无效分页，详情按需 |
| 20 账号／500 对象 | 搜索目录；当前／异常优先，其他组收起；“查看全部”可达 |
| 100 账号／500–2000 对象 | 分页或按需渲染；不预展开整页，不按账号数量无限并发 |
| 空、长名称、全失败、混合缓存 | 每种状态独立可辨，不用零值和整齐卡片掩盖事实 |

- 分页单位写清是账号还是对象；导出覆盖完整筛选结果，不仅当前可见页。
- 数据未读／读取失败／成功空集／真实零／旧缓存分开；绑定数量不等于验证成功数量。
- 指标保留值、单位、范围、日期、读取时间、来源和覆盖。数值与图形使用同一计算结果。
- 多账号风险只看已知最高值时明确覆盖；没有全覆盖不能断言“全部正常”。
- 选择对象被过滤或删除后清理失配检查器，不展示上一对象残留信息。

## 6. 图形语言的使用清单

| 表达 | 适用 | 不适用／限制 |
| --- | --- | --- |
| 点阵／分段梯条 | 域名状态构成、账号可用名额等明确计数 | 不取代名称；超过单位容量需明确映射和精确数字 |
| 规范化容量尺 | 账号额度压力、距自身上限 | 所有条统一 0–100%；绝对容量另标，不混尺度 |
| 共同数量尺 | 不同账号拥有的额度／资源数量 | 使用同单位与同尺度；未知不画成零长度 |
| 时间基线 | 最近注册、日志、真实 DDNS 事件 | 无历史不造曲线，时间顺序与日期可追溯 |
| 日请求柱／折线 | 已取得的 CF 日期序列 | 不把快照拼成历史，不逐账号永久占半屏 |
| 状态矩阵 | CF 资源可读性、账号诊断 | 状态有文字，不靠彩色圆点解释全部 |

Lieflat Charts 用于选择图表与约束交互，不当成图表装饰库；不因用户喜欢梯子就把每个数值画成梯子。OpenDesign 有可验证稿件时用于模块对照；无 artifact 或认证不可用如实记录，不重复空跑、不声称已经出稿。

## 7. 最小必要的代码结构调整

1. 保持服务与既有业务命令；从当前页面共享同一组过滤后的对象、选中 ID 和命令。
2. 划分“业务数据状态／查询范围／局部交互／呈现风格”。折叠、排序、详情不能各风格各算一份。
3. 两种风格仅分别组合页面骨架与视图；日期、用量、权限、额度计算共用模型。
4. 先拆本轮受影响工作面，逐步缩小 `App.tsx`；不将全文件重写与视觉改版绑定。
5. 类型与数据契约先覆盖可空值、权限与缓存；不以 CSS 隐藏坏状态解决问题。

### 验收与回归补齐

- **对象可找**：准确定位域名、账号、密钥；鼠标与键盘都能打开对应详情。
- **动作真实**：折叠改变当前正文；刷新出现新数据；Key／Secret 可查看复制；内部动作不误触父行。
- **图形诚实**：A 110%、B 0% 不得得到“整体安全55%”；未知不变 0；所有比较使用共同尺度。

- **节奏**：先定向，阶段完整回归；后台 headless，不碰前台键鼠，不停止用户进程。

## 11. 2026-10-17 用户复审收敛：下一轮重构基线

本节是对前述方案的优先级收敛，不改变数据契约和候选／生产边界。用户已明确：设计风不能只是卡片材质变化；数据风不能只是把设计风压成表格。以下决定优先于历史截图中的旧排版。

### 11.1 概览

- **数据风**合并三类已验证有价值的信息：域名状态总量（带明确分母）、账号配额比较、CF 免费额度摘要；保留最近注册作为低高度事件轨道。域名状态必须同时显示总量、已委派／未委派、活跃／过期，CF 必须显示已读用量、单账号额度、最高单账号压力与覆盖数。
- **设计风**保留用户认可的域名资产、账号／助力和账户配额层次；重做“最近注册”和“CF 免费额度”模块，使其成为时间基线与容量证据，而不是普通等高卡片。
- 两个风格共享同一查询结果；不得将多账号上限相加后计算“整体安全百分比”。

### 11.2 域名列表与 Cloudflare

- 设计风保留域名基线／对象目录的视觉语言，但**正文必须有名称、账号、状态和日期**；点阵只做汇总或筛选入口，不能代表大量域名的唯一定位方式。
- 数据风保留卡片／表格切换、搜索、排序、分组折叠、导出和整组收起。工具带采用“筛选 → 统计 → 动作”三段结构，导出／收起不再贴着发丝线或撑高统计卡。
- Cloudflare 与域名页共用这套资产骨架，但正文以 Zone 名称、NS／激活／可读性和下一步动作作为列；失败账号必须保留，不显示为 0 个 Zone。

### 11.3 助力、账号与 API 密钥

- 助力设计风改为“输入／确认区 + 可参与账号队列 + 历史轨道”，账号和域名明细默认按组收起；数据风保留额度比较和可筛选行。
- 账号管理保留顶部 DNSHE／Cloudflare 绑定控件。设计风使用连接目录与权限检查器；数据风使用提供商分组表。绑定、验证、资源可读三种状态分开表达。
- API 密钥统一为 Key Ledger：名称、状态、请求量、最后使用时间沿共同列线；点击整行打开二级检查器查看 Key／Secret。删除无效备注与装饰性轨道，Secret 继续由显示／隐藏／复制安全控件处理。

### 11.4 注册查重、配额与 DDNS

- 查重页固定为“单个／批量／历史”三个工作面；两位数字等快捷规则显示真实候选数，批量任务可暂停、继续、停止并写入可恢复历史。
- 账户配额页保留当前可用的数据结构；设计风仅重做容量尺、重点账号和按需分解，不引入无意义图表。
- DDNS 设计风与数据风都必须支持真实绑定与明确标注的模拟场景；模拟数据不得冒充真实事件。

### 11.5 CF 免费额度与运行日志

- CF 免费额度页删除页内“设计／数据”切换，只服从顶栏全局风格。首屏结构固定为“范围／刷新 → 状态带 → 账号比较表”；整行点击展开，详情紧跟对应账号，键盘与焦点恢复不变。
- 设计风仅保留一张适度高度的完整趋势图与峰值旁注；数据风优先状态、比较、筛选和微趋势。文案压缩为事实状态，详细接口、权限、范围和原始错误放诊断折叠区。
- 权限修复按“接口 → 权限 → 模板 key/type → 账号范围”逐项核对；已有 Token 不会因模板更新自动升级。Pages `Authentication error` 必须区分权限、Token policy、账号范围、服务未启用、历史窗口不足和网络失败。
- 运行日志刷新必须产生真实 GET 请求、保留旧数据和最近成功时间；用户停在旧位置时显示新日志数量，不强行抢滚动。

### 11.6 下一轮实施顺序与门槛

1. **P0 数据与真实性**：概览 CF 单账号压力口径、CF 权限链路与缓存诊断、API 密钥批量读取／缓存、日志刷新实网请求。
2. **P1 结构与密度**：概览双风格合并／重排、资产工具带、助力折叠、账号／密钥检查器、CF 账号行详情。
3. **P2 新工作面**：查重历史恢复、DDNS 真实／模拟双风格、配额设计风、统一状态与空态文案。
4. **阶段验收**：先跑定向行为与数据语义，再跑构建、几何、浅深主题和 390／768／1440／1920 截图；通过后才更新候选 2。生产不修改。

本节完成前，不把新的截图或合成夹具称为“用户已接受设计”；每个页面的交付必须同时列出真实数据范围、交互证据、几何证据与尚未解决的上游限制。

## 12. 2026-10-17 最新复审：逐页重构执行蓝图

本节把用户对 4 张当前截图的复审与子智能体的设计／实用性审查合并为下一轮执行基线。它不是再做一轮“换颜色”的视觉调整，而是把每页的主任务、信息密度、数量规模和操作路径重新固定下来。

### 12.1 当前截图结论

- **概览设计风**：Domain Atlas 的共同基线、账号轨道和右侧对象检查器已经有识别度，保留；但 53 个域名、CF 免费额度和最近注册没有形成同一条“总量 → 压力 → 下一步”叙事，首屏仍缺少总量与资源使用的结论。
- **域名列表数据风**：表格、分组、搜索和卡片／表格切换是有效设计；导出／收起贴在工具带发丝线旁，形成拥挤的第三排，必须改成同一 footer 内的“统计 → 导出 → 收起”尾轨。
- **账号绑定**：双按钮是当前最清楚、最可用的动作区，保留作为数据风和设计风的共同主动作，不再包成无意义卡片。

### 12.2 全局信息架构

#### 全局画风

- 顶栏只保留一个全局切换：`设计`／`数据面板`；CF 免费额度页删除页内重复切换。
- `设计`改变阅读顺序与对象组织：结论 → 对象身份 → 证据 → 下一步。
- `数据面板`改变阅读顺序与操作组织：异常 → 范围／筛选 → 比较 → 行级动作。
- 两套模式共享同一查询结果、搜索、排序、折叠、选中对象和草稿，不重复请求，不清空状态。
- 黑白灰为结构色；状态色仅表示成功、警告、危险。禁止渐变、辉光、紫粉蓝 AI 色、装饰箭头和无意义英文眉题。

#### 通用页面壳

1. 页面标题区：标题、范围、最近读取时间和一个主动作。
2. 结论／状态带：最多 4 个关键事实，不做四张等权 KPI 卡。
3. 主工作面：使用共同列线或共同边缘；卡片只承载对象身份，表格只承载比较和筛查。
4. 检查器：仅在选中对象后出现，紧跟对象或固定右栏，不在底部追加“幽灵详情”。
5. 反馈：刷新、失败、缓存、权限、空集和真实零必须分开表达。

| **账户配额** | 重点账号容量尺 + 按需展开的基础／助力／可用额度 | 统一 0–100% 压力比较表，旁列已用／总额／可用／状态 | 不混用百分比尺度和绝对数量尺度；超额可超过 100%，失败不得排成最低压力 |
| **动态 DNS** | 绑定对象、最近 IP、最近执行和下一步动作；真实与模拟用同一骨架 | 任务状态表：正常、IP 未变、超时、重试、从未更新 | 模拟数据必须显式标识；不得伪造实时事件或把模拟状态混入真实绑定 |
| **CF 免费额度** | 结论 + 资源容量尺 + 一张适度高度的完整趋势 + 峰值旁注；账号明细按需展开 | 范围／刷新 → 状态带 → 账号比较表 → 微趋势／诊断；整行点击展开并紧跟当前账号 | 删除页内设计／数据切换；压缩重复说明；权限、缓存、历史覆盖、服务未启用、范围不符分开显示；趋势只在有可靠日期序列时显示 |
| **运行日志** | 日期／事件时间线，按行展开详情 | 时间、级别、模块、对象、消息列；筛选、刷新、清空为明确动作 | 刷新必须产生真实 GET；停在旧位置时提示新增条数，不强抢滚动；最近 100 条限制明示 |

### 12.4 图形与组件规则

- 点阵／节点：只用于域名状态构成、账号可用名额等有限数量摘要；超过单位容量必须同时显示精确数字。
- 梯条／压力轨：只用于单账号额度压力；统一 0–100% 基线，超额溢出，不用颜色猜值。
- 时间基线：用于最近注册、日志、DDNS 事件；无历史就不画线。
- 趋势图：一张图只回答一个问题；默认高度 180–260px，提供完整日期命中区、Tooltip、键盘焦点、零值／缺失语义和动态轴。
- 表格：桌面使用共享列轨道，移动端改对象行；名称、状态、时间和主动作必须可见，不允许 8 列压缩到 390px。
- 控件：每页最多一个 Filled 主动作；导出、收起、刷新、复制等使用边线或文本动作；危险动作保留确认。
- 文案：`Notes` 统一为“笔记”；删除解释性套话，保留范围、时间、单位、来源、覆盖率和下一步。

### 12.5 数据与权限真实性

1. 先列出每页实际调用的接口、字段、账号／Zone 范围和时间窗口。
2. 每个值标记 `fresh / cached / unknown / permission / error / empty / zero`，未知不能显示成 0。
3. CF Pages `Authentication error` 必须分别核对 Token 权限、Token policy、账号范围、服务启用、历史窗口和网络失败；修改模板不升级旧 Token。
4. “一键申请权限”必须以接口清单为源生成；申请后仍显示实际返回的缺失项，不能用 URL 中包含权限字符串当作修复证据。
5. 运行日志、CF 刷新、API 密钥读取必须显示本次刷新是否成功；可读旧缓存是恢复能力，不是 fresh 成功。

### 12.6 实施批次与验收门槛

- **P0 真实性**：CF 权限清单与资源诊断、API 密钥超时／并发／快照、日志刷新请求、概览总量与 CF 单账号压力。
- **P1 结构**：概览合并、域名／Cloudflare 工具带、助力分组折叠、账号检查器、Key Ledger、CF 行级详情。
- **P2 工作面**：查重历史与批量、DDNS 真实／模拟、配额设计风、统一空态／失败文案。

## 13. 复审后的视觉验收补充（2026-10-17）

“设计感”不再以 Domain Atlas、轨道、检查器等名词证明。每页交付必须拿同一夹具并排比较设计风／数据风，并至少满足以下两项可见差异：

1. DOM 工作面或阅读顺序不同；
2. 对象身份、状态、时间、数值共享列轨或共同边缘；
3. 主动作位置或选中对象的检查器位置不同；
4. 同一事实在设计风为结论／证据，在数据风为筛选／行级动作。

只改变阴影、圆角、颜色、字号或留白，视为验收失败。设计风也必须保留真实名称、状态、动作与失败恢复，不能用空白、无名点阵或装饰性图形替代功能。
