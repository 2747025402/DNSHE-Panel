# DNSHE 页面数据地图与图表契约

更新：2026-10-17。本文把页面的数据对象、阅读任务与呈现方式分开；它不是把每页强行做成监控大屏的改版清单。

## 设计边界

- 全局画风只决定信息骨架：设计风回答“发生了什么、对象是谁、下一步是什么”；数据面板风回答“哪里异常、按什么筛、哪一行要处理”。
- 页面内的“卡片／表格”是同一数据集合的视图切换，不是第二套数据源。数据页可以在不丢筛选、排序、展开状态的前提下切换。
- 图表只承担一个结论，保留单位、时间范围、覆盖数和缺失语义。没有真实序列时不画装饰性折线。
- 黑白灰为默认结构色；颜色只表达成功、警告、危险或品牌身份。

## 页面数据与表达矩阵

| 页面 | 主要对象与字段 | 主阅读任务 | 首选表达 | 不使用 |
|---|---|---|---|---|
| 概览 | `OverviewData.domains`、`accounts`、`quota`、`assist`、最近注册 | 判断资产总况和下一步 | 结论带 + 资产状态轨道 + 最近变化；数据风可切比较表 | 四张等权 KPI 卡、无单位环图 |
| 域名列表 | `Domain[]`：完整域名、状态、注册/到期、DNS 来源、账号、操作 | 找到对象并立即进入 DNS/委派/续期 | 设计风分组对象卡；数据风共同列线表；两者在页内切换 | 按域名画折线、重复元数据卡 |
| Cloudflare | `Domain[]` zone、账号、状态、NS、远端 ID | 判断 zone 是否可管理、进入解析或传播检查 | zone 分组卡/资产表；状态矩阵与动作尾轨 | 环图、用颜色替代状态文字 |
| 账号管理 | `Account[]`：别名、API key 掩码、提供商、绑定时间 | 管理凭据身份与绑定关系 | 账号身份卡或两组对齐行；操作列固定在尾部 | 账号数量折线、虚假的健康评分 |
| 账户配额 | `Quota[]`：已用、基础额度、助力额度、总额、可用、错误 | 比较可用额度和异常账号 | 比较条/数值表；卡片与表格同源切换 | 饼图、把多账号相加再除单账号上限 |
| CF 免费额度 | `AccountUsage[]`：Workers/D1/KV/R2、请求历史、权限、缓存时间 | 先定位异常，再追溯趋势 | 数据风状态带 + 账号比较表 + 微趋势；设计风趋势证据 + 峰值旁注 | 大面积单账号折线、缺失当零 |
| API 密钥 | `ApiKeyGroup[]` / `ApiKeyRow[]`：名称、状态、请求数、最近使用、创建时间 | 找到密钥并判断是否仍在使用 | 分组表；请求数仅作列值或微条 | 没有时间序列时画趋势 |
| 运行日志 | `AppLog[]`：时间、级别、分类、对象、详情 | 定位一次失败和恢复路径 | 时间线/事件表；日志详情按行展开 | KPI 卡、按日志数量画饼图 |

| 注册/查重 | 扫描输入、候选域名、可用性、日志、断点 | 快速决策并继续扫描 | 步骤状态带 + 结果列表 + 可暂停操作 | 候选数量折线、装饰性进度环 |
| 域名助力 | 账号、助力剩余、域名状态、历史记录 | 找到可助力对象并确认消耗 | 分组对象卡 + 进度轨道 + 历史时间线 | 把不同账号额度合并成一个百分比 |
| 设置 | 表单值、配置状态、保存结果、支持名单 | 修改配置并知道是否生效 | 分组表单、状态条、失败保稿 | 图表和大面积空白卡片 |

## 图表角色

- **Lupi / Basics**：用于设计风的完整趋势。横轴是明确日期或采集时间，点位有完整命中区，tooltip 显示单位、账号、覆盖和缺失；适合 CF 用量与近期变化。
- **Glance**：用于数据风的监控快读。状态带、比较条、表内微趋势优先于大图；每个图只回答一个筛查问题。
- **压力条 / Rung**：单值额度和多账号比较；数值与总额并列，不能只给颜色。
- **时间线 / 事件行**：日志、DDNS 最近执行、助力历史；异常原因留在原行，支持展开。
- **状态矩阵**：Cloudflare zone 与 DDNS 多状态对象；行是对象，列是可读性、权限、最近同步、下一步。

## 页面内视图合同

1. 卡片与表格必须引用同一个过滤后的数组；切换不重置搜索、账号范围、排序、页码和展开行。
2. 桌面端表格共享列轨道，移动端改为带字段标签的对象行；不把 8 列表格压到 390px。
3. 设计风保留对象身份、分组和浏览层次；数据风保留状态带、固定数值轨道和行级动作。圆角、阴影、字号不是模式差异的主证据。
4. 真实零、不可用、权限不足、读取失败、旧缓存必须有不同文字；不可用不画成 0。
5. 每个页面至多一个 Filled 主动作；其余动作采用边线或文本动作，危险操作保留确认。

## 当前实施顺序

1. 概览／CF 免费额度：保留现有数据契约，补小型趋势与数据状态分流。
2. 域名／Cloudflare／账户配额：统一卡片与表格切换入口，共用筛选和列轨道。
3. 日志／DDNS／API 密钥：补事件、任务和密钥的状态骨架，不新增假数据。
4. 注册／助力／设置：只做密度与动作层级优化，不用图表填空。
